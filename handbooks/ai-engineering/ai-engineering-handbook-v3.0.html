01

LLM Mechanics & Tool Use

Foundation · The atomic loop
+

Pareto Focus

  • Attention as retrieval: You don't need the math. Context window = RAM. Attention = similarity search across that RAM.
  • The atomic loop: User → LLM → JSON → Tool → Result → LLM → Answer. Every agentic system is this loop, repeated.
  • Structured output: JSON mode + Pydantic parsing turns stochastic text into reliable software interfaces.
🧠 Feynman checkpoint
"An LLM is a probabilistic autocomplete engine. Tool calling forces it to emit a JSON function call instead of prose. The magic is in the loop, not the model."

Build: Atomic Agent

A 100-line Python script that takes a user query, decides between three tools (web search, calculator, weather), executes the chosen tool, returns structured JSON.

Success criteria: Handles 10 diverse queries without schema violations.

02

Prompt & Context Engineering

Foundation · Prompts are code
+

Pareto Focus

  • Six-block template: Role → Context → Task → Format → Rules → Examples. Use it as a starting structure, then test which blocks materially improve the task.
  • Reasoning support: Ask for explicit plans, checks, evidence, or intermediate artifacts when the task needs them; evaluate the final result rather than assuming visible reasoning guarantees correctness.
  • Context = RAM: What you put in (retrieved docs, memory, tool schemas) matters more than how you phrase the question.
🧠 Feynman checkpoint
"Prompts are code, not prose. We version them, test them, deploy them through CI/CD. A prompt change is a code change."

Build: Prompt Versioning System

Git-tracked prompt registry. Jinja2 or YAML templates separate from code. A/B test two variants against a 20-example eval set. Measure correctness, latency, token cost.

03

RAG Foundations

Retrieval · Runtime knowledge injection
+

Pareto Focus

  • Chunking: A 512-token chunk with modest overlap is a baseline experiment, not a default. Iterate using retrieval and end-task evaluation.
  • Embeddings: text-embedding-3-large (cloud) or bge-large-en-v1.5 (open). The embedding model matters less than chunk quality.
  • Hybrid search: Compare dense, sparse (BM25), and fused retrieval on the actual corpus; hybrid retrieval is valuable when lexical precision and semantic similarity are both needed.
🧠 Feynman checkpoint
"RAG is runtime knowledge injection. Instead of asking the LLM to remember everything, we Google our own documents at query time and paste the top results into the prompt."

Build: Document Q&A Pipeline

Ingest 20 PDFs → chunk → embed into pgvector. FastAPI endpoint retrieves top-5 chunks and generates an answer with citation markers. Success criteria: 80%+ groundedness measured by LLM-as-judge.

Resources

04

Agentic RAG & Memory

Retrieval · Self-evaluating loops
+

Pareto Focus

  • Agentic loop: Retrieve → Evaluate sufficiency → Reformulate → Re-retrieve (max 3 iterations) → Generate. The agent decides when it knows enough.
  • Three memory tiers: Short-term (conversation), Semantic (user facts in vector DB), Episodic (past decisions as few-shot). Procedural is nice-to-have.
  • Query reformulation: HyDE (Hypothetical Document Embedding) and step-back prompting actually move the needle. Most other tricks don't.
🧠 Feynman checkpoint
"Static RAG retrieves once and hopes. Agentic RAG asks: 'Is this enough?' If not, search again with a better query. It's a researcher checking sources before writing."

Build: Self-Evaluating Research Agent

Extend Week 3. Add sufficiency-evaluator node, query reformulation, semantic memory in pgvector. Evaluate on a 30-question test set measuring retrieval recall, faithfulness, latency.

05

LangGraph Deep Dive

Agent core · State machines over chat loops
+
📌 September 2026 status

LangGraph 1.2.11 was the current PyPI release on 3 September 2026. Its maintainers describe it as a low-level orchestration framework for long-running, stateful agents, with production users including Klarna, Replit, and Elastic. Treat it as one mature option, not a universal default: select it when explicit state, durable execution, and controlled orchestration fit the workload.

Pareto Focus

  • State machines, not chat loops: Explicit nodes (functions) and edges (transitions) make agents debuggable.
  • Checkpointing: Persistence turns a script into a product. Users can resume, rewind, inspect.
  • Human-in-the-loop: interrupt nodes for approval. Non-negotiable for any agent with write access.
🧠 Feynman checkpoint
"LangGraph forces you to draw the flowchart before you write the code. If you can't draw the state machine on a whiteboard, your agent will fail in production."

Build: Approval-Required Agent

Plans a multi-step task (research → write → send). Pauses at "send" for human approval via a simple web UI. Resumes or aborts based on input. Persists state to PostgreSQL. Success criteria: kill the process mid-task, restart, it resumes correctly.

Current LangGraph concepts and versioning docs CrewAI deep dive (prototyping only) AutoGen / Semantic Kernel deep dives (use Microsoft migration guidance if inherited)

MCP & the Tool Ecosystem

Agent core · USB-C for AI
+
📌 September 2026 status

MCP is governed through the Linux Foundation's Agentic AI Foundation. Anthropic's December 2025 donation announcement reported 10,000+ active public servers and 97M+ monthly Python and TypeScript SDK downloads; treat those as dated adoption figures, not live counters. The latest specification on 3 September 2026 was 2026-07-28. MCP is a widely adopted open standard for connecting AI applications to tools and context.

Pareto Focus

  • MCP is USB-C for AI: One standard for tools. Learn once, use everywhere.
  • Build > consume: Building one MCP server teaches you more than consuming ten.
  • Schema-first design: Typed tool interfaces make agent-tool integration failures easier to detect, test, and contain.
🧠 Feynman checkpoint
"MCP is a contract. The server says 'I have a calculator tool that takes two numbers.' The client says 'I need to calculate something.' MCP translates so any LLM can use any tool."

Build: MCP Server + Client

An MCP server exposing a SQLite database (product catalog). Connect to your LangGraph agent from Week 5. Connect the same server to Claude Desktop. Document the schema with OpenAPI-style descriptions.

Evaluation & Observability

Production · Eval-driven development
+

Pareto Focus

  • EDD: Define your eval set before your agent. If you can't measure it, you can't ship it.
  • Three-level eval: Outcome (did it finish?), Trajectory (was the path reasonable?), Per-step (was each tool call correct?).
  • Langfuse: Self-hostable, OpenTelemetry-native, LangGraph-aware. The pragmatic choice for solo developers and small teams.
🧠 Feynman checkpoint
"Evaluation is the entire game. Anyone can get a demo working. The engineer who can prove it works at scale — with numbers — is the one who gets hired."

Build: Eval Harness

30 (input, expected_output) pairs as a golden dataset. LLM-as-judge scoring (faithfulness, relevance). Langfuse tracing on every node. CI script fails if faithfulness < 85%.

Safety, Guardrails & Cost Control

Production · Defense in depth
+

Pareto Focus

  • Defense in depth: Input validation → Output guardrails → Budget limits → Audit logs. No single layer suffices.
  • Cost is a feature: Eval-qualified routing can reduce cost by using expensive models only where they improve accepted-task outcomes.
  • Prompt injection: The SQL injection of AI. Mitigate with privilege separation and tool allow-listing, not prompt cleverness.
🧠 Feynman checkpoint
"Safety isn't a bolt-on; it's architecture. You don't secure a bank by hiring better tellers; you secure it with vaults, cameras, and alarms."

Build: Hardened Agent

Add to Week 6 agent: input regex guard, output PII redaction, token budget per session (10K in / 2K out), cost dashboard, audit log of every tool call and approval.

Multi-Agent & Capstone Design

Integration · When (not) to multiply agents
+

Pareto Focus

  • Multi-agent is a scaling tool, not a default. Compare against a strong single-agent baseline and use multiple agents only when decomposition or independent review creates measured value.
  • Supervisor pattern: One coordinator, specialist workers. Easiest to debug, easiest to scale.
  • Plan-and-execute: Capable model plans, cheap model executes. The single best cost-optimization pattern.
🧠 Feynman checkpoint
"Multi-agent is hiring a team. If one person can do the job well, more people creates meetings, miscommunication, delay. Only go multi-agent when the work genuinely requires different expertise."

Capstone: Enterprise Research Agent

Planner → Research Agent (MCP search) → Writer Agent → Review Agent → Human Approval → Output. LangGraph state, Langfuse tracing, cost tracking.

Five core architectures.

Every production agentic system is one of these — or a composition

1 · Single agent with tools

User → Agent → Tools → APIs → Results

Use for: Assistants, coding tools, research agents, support bots.
Framework: OpenAI Agents SDK (fastest), LangGraph (most control).

2 · Planner – Executor

User → Planner (capable model) → Task list → Executor (cheap model) → Tools

Use for: Report generation, complex research, structured workflows.
Benefit: Potentially lower cost per accepted result when routing quality is proven by evaluation.
Framework: LangGraph (natural fit), CrewAI Hierarchical Process.

3 · Multi-agent collaboration

User → Manager Agent → Specialist Agents → Results

Use for: AI dev teams, content pipelines, complex cross-domain tasks.
Caveat: Coordination adds latency, cost, and failure modes. Use it only when decomposition or independent verification beats a strong single-agent baseline.

4 · Event-driven

Event (CRM lead, ticket, alert) → Agent → Decision → Action

Use for: Sales automation, DevOps, ops workflows.
Framework: n8n (no-code), LangGraph + Redis/Kafka (code-first), Temporal (durable).

5 · Self-improving (bounded)

Agent → Action → Feedback → Memory update → Agent

Use for: Personal assistants, long-running research, recommendation systems.
Reality check: Most "self-improving" production systems are human-curated refinement loops. Full autonomy remains research-grade.

Three unsolved problems · 2026

These remain the primary barriers to fully autonomous production agents. Recognizing them keeps you honest in interviews.

⚠ Unsolved · 01

Long-term memory

Problem: Agents forget across sessions. Context windows are expensive and degrade with length.

Practical baseline: Hybrid — hot-path context + vector semantic memory + background consolidation.

Gap: Cross-agent memory sharing, provenance tracking, contamination prevention.

⚠ Unsolved · 02

Reliable planning

Problem: Agents lose track of progress, replan poorly on failure, or over-decompose trivial tasks.

Practical baseline: Explicit task graphs (LangGraph), execution monitoring, plan verification via a second model.

Gap: Hours-long autonomous workflows with reliable replanning.

⚠ Unsolved · 03

Observability at scale

Problem: We can trace everything, but interpreting traces — "why is this agent slowly degrading?" — is largely manual.

Practical baseline: Langfuse / OpenTelemetry traces, model-based judging for sampled grading.

Gap: Automated root-cause analysis for agent failures.

Decision trees

RAG vs Fine-tuning

Can better prompting solve it? → YES: do that. ↓ NO Can RAG solve it? → YES: do that. ↓ NO Can few-shot examples solve it? → YES: do that. ↓ NO Consider fine-tuning (LoRA) with 1K+ high-quality examples.

Single agent vs Multi-agent

Task is deterministic with clear steps? → Workflow (LangGraph DAG) ↓ Task needs reasoning + 2–5 tool calls? → Single Agent (ReAct) ↓ Task decomposes into distinct expertise domains? → Multi-Agent (Supervisor) ↓ Task requires debate / consensus? → Peer-to-Peer (research only)

Cloud vs Edge deployment

Latency < 200ms? → Edge (SLM on-device) Data cannot leave premises? → Edge or private cloud Complex reasoning required? → Cloud (frontier LLM) High volume, cost-sensitive? → Hybrid (SLM edge + LLM cloud fallback)

Evaluation pyramid.

Build from the bottom up · most teams skip the cheap layers

Most teams skip the cheap layers and go straight to LLM-as-judge, then wonder why evals are noisy and expensive. Build bottom-up.

┌──────────────────┐ │ Human eval │ ← Periodic calibration (quarterly) │ (gold standard)│ └──────────────────┘ ┌──────────────────────┐ │ LLM-as-judge │ ← Every PR / model change │ (RAGAS, G-Eval) │ └──────────────────────┘ ┌──────────────────────────────┐ │ Schema validation │ ← Every commit │ Exact match, code exec │ Fast, cheap, deterministic │ Structural assertions │ └──────────────────────────────┘

Layer 1 · Structural validation (commit-level)

  • JSON schema compliance (Pydantic validators)
  • Tool-call signature verification
  • Regex guards for format compliance
  • Code-execution tests for code-gen agents

Layer 2 · LLM-as-judge (PR-level)

  • RAGAS: faithfulness, answer relevance, context precision / recall
  • DeepEval G-Eval: chain-of-thought reasoning before scoring
⚠ Calibration rule

Do not trust an LLM judge until it has been calibrated against a representative human-labelled set with an agreement threshold appropriate to the decision risk.

Layer 3 · Human evaluation (quarterly)

  • Likert ratings on a sampled subset
  • Error-taxonomy tagging (retrieval failure, reasoning error, hallucination, tool misuse)
  • Inter-annotator agreement (κ > 0.6 is the bar)

The three-level agent eval

Evaluate at all three levels or you'll miss critical failure modes.

LevelQuestionMetricsTools
OutcomeDid the task complete successfully?Task success rate, CSAT, deflection rateProduction analytics
TrajectoryWas the path reasonable?Steps to completion, tool selection accuracy, loop detectionLangfuse traces
Per-stepWas each individual action correct?Tool param accuracy, retrieval precision@k, latencyCustom assertions

Anti-patterns to avoid

  • Outcome-only eval: misses agents that get lucky or take inefficient paths
  • Trajectory-only eval: punishes valid creative paths
  • Static eval sets: your data drifts; your eval set should too. Refresh monthly.

The interview playbook.

Five questions that separate read-the-docs from shipped-in-prod

Q1

Walk me through naive RAG → advanced RAG → agentic RAG.

Tests RAG depth · retrieval reasoning
+

Strong answer structure

  1. Naive: embed → vector search → stuff into prompt → generate. Fast, simple, fails on complex queries.
  2. Advanced: add hybrid search (BM25 + dense), reranking (cross-encoder), query rewriting. Better recall, still static.
  3. Agentic: agent evaluates sufficiency, reformulates query, iterates retrieval (max N times), then generates with citations. Dynamic, slower, higher quality.
Senior signal: mentions latency trade-offs, cost per query, and when each tier is appropriate.
Q2

Your RAG hallucinates despite good retrieval. Debug it.

Tests systematic thinking
+

Strong answer · ordered

  1. Verify retrieval is actually correct (log chunks, measure recall@k).
  2. Check prompt instructions: "Answer ONLY from context."
  3. Check context positioning (lost-in-the-middle; move best chunks to start/end).
  4. Check chunk granularity (too large dilutes signal; too small fragments facts).
  5. Add faithfulness check (LLM-as-judge or NLI model) before returning the answer.
  6. If all fail, the question likely isn't answerable from the corpus.
Q3

When do you NOT use an agent?

Tests judgment · anti-agent-washing
+

Strong answer

  • Deterministic workflow → use a DAG / state machine.
  • Sub-second latency budget → agent loops add seconds.
  • High cost of failure (finance, medical) without HITL → too risky.
  • Simple RAG or single tool call suffices → don't over-engineer.
  • A strong single-agent baseline already meets the acceptance target and the task does not decompose cleanly → multi-agent complexity is unlikely to earn its cost.
Q4

How do you cut LLM costs by 50% without quality regression?

Tests optimization · economics
+

Strong answer · three tiers

  1. Don't call the LLM: semantic + exact caching, trivial query classification to non-LLM paths.
  2. Call a cheaper LLM: route tasks that pass an eval-backed confidence threshold; use the larger model as a controlled fallback.
  3. Make each call cheaper: prompt compression, shorter contexts, output token limits, quantization, batch inference, prompt caching.
Critical

Validate every change against the eval harness. Cost cuts without measurement are just quality cuts in disguise.

Q5

Explain MCP in 60 seconds.

Tests current-state knowledge
+

Strong answer

"MCP is an open interface for AI applications to access tools and data — like USB-C for AI. Its server primitives are Tools (execute functions), Resources (expose context), and Prompts (reusable templates). A server exposes capabilities; a client consumes them. Compatible hosts can reuse the same capability boundary instead of building a bespoke integration for each tool. MCP moved under the Linux Foundation's Agentic AI Foundation in December 2025; the latest specification reviewed here is 2026-07-28."

System design scenarios

A

Customer support chatbot · 100k QPS · < 2s latency

High-volume RAG + tool use
+

Architecture

  1. Intent classifier (small model, < 50ms) routes simple FAQs to cached responses.
  2. RAG pipeline (hybrid search + rerank, < 200ms) for complex queries.
  3. LLM (quantized open-weight or API) with constrained JSON output.
  4. Tool layer (order lookup, refund) via MCP with HITL for write operations.
  5. Guardrails: input filtering, output PII redaction, toxicity detection.
  6. Fallback: confidence threshold routes to human with full context.

Key trade-offs

  • Latency vs quality: reranking adds latency but may improve precision; measure both on the target corpus.
  • Cost vs coverage: use an eval-qualified open-weight model for suitable routine traffic and a stronger API model for defined edge cases.
B

Real-time fraud detection · < 50ms

Why an LLM is the wrong tool
+

Architecture

  1. Feature pipeline: Kafka → Flink for real-time aggregations.
  2. Model: XGBoost or LightGBM — not an LLM. Deterministic, fast, explainable.
  3. Inference: ONNX Runtime, co-located with feature store.
  4. Decision: score → policy engine (allow / step-up / block).
  5. Explainability: SHAP values surfaced to analysts.
Why not an LLM? Latency budget and deterministic requirements. Use the right tool for the job.

Behavioral · STAR templates

S1

Tell me about a model that failed in production.

+
Situation: At [Company], our demand-forecasting model's MAPE jumped from 9% to 17% overnight after a deployment. Task: I owned the ML pipeline and had to diagnose and fix it before the weekly replenishment run. Action: 1. Rolled back via feature flag within 15 minutes. 2. Checked data drift — PSI on input features showed an upstream schema change (new POS field mapping). 3. Fixed the ingestion pipeline, added schema validation (Great Expectations), and retrained. 4. Added a canary stage (1% traffic) to the deployment pipeline. Result: Zero business impact due to fast rollback. Schema validation now blocks known incompatible changes before they hit the model. Post-mortem became our template for incident response.
S2

How do you handle ambiguity?

+
Situation: Stakeholders asked for an "AI assistant" without defining success metrics or scope. Task: Create clarity and a viable 6-week plan. Action: 1. Ran a 2-day discovery workshop with 5 stakeholders. 2. Defined the primary metric (deflection rate) and guardrails (CSAT, escalation rate). 3. Scoped a 2-week MVP (RAG over 500 FAQs) to validate feasibility. 4. Wrote a one-pager with architecture, risks, and go/no-go criteria. Result: MVP achieved 40% deflection rate. Stakeholders approved full build. The one-pager became our project charter.

  • Claude's active lineup changed. Anthropic now lists Fable 5.1, Opus 5, Sonnet 5, and Haiku 4.5. Select by eval results and workload economics rather than treating one model as a permanent default.
  • MCP matured. It remains under the Linux Foundation's Agentic AI Foundation; the latest specification reviewed on 3 September 2026 is 2026-07-28 and includes optional extensions for tasks, skills, and MCP Apps.
  • LangGraph stayed on the 1.2 line. PyPI listed 1.2.11, released 11 August 2026. It is a mature low-level option for explicit, long-running stateful orchestration—not an automatic choice for every agent.
  • The EU AI Omnibus entered into force on 27 July 2026. Annex III high-risk rules now apply from 2 December 2027; Annex I product-embedded high-risk rules apply from 2 August 2028.
  • Agent protocols are separating concerns. MCP covers tools and context, A2A covers agent interoperability, and AG-UI covers agent-to-frontend events. Treat each implementation as a maturity and security decision.
  • Microsoft Agent Framework 1.0 is production-ready. Microsoft directs inherited AutoGen and Semantic Kernel users to its migration guidance; new projects should compare it with LangGraph and other runtimes against explicit requirements.

Quarterly refresh checklist

This handbook will go stale. To keep it current, run this loop every quarter:

  1. Verify current model IDs and pricing against the official Anthropic / OpenAI / Google docs.
  2. Check LangGraph version (PyPI) and re-pin dependencies.
  3. Re-read the latest MCP spec changelog at modelcontextprotocol.io.
  4. Re-check the EU AI Act implementation timeline and any subsequent amendments against official EU sources.
  5. Skim Anthropic's applied-llms.org and the LangChain blog for new patterns.
  6. Audit external links (link rot is real on personal blogs and vendor startup sites).
